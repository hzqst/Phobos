# 决策 对象层记录绘制调用而非按状态重推

## 背景
D2、D3b、D3a-1 在 4F4583 按对象当前状态重推 RenderLayers（6D8DB0）的 SHP 参数（AnimImage.h、UnitImage.h、DoorAnim）。到 SHP 车辆（D3a-2）时，Ares 3.0p1 与 Phobos 在 73C5F0/705E00 一带有十几个 hook（朝向、换类型、阴影次序、水面类型、矿车动画、炮塔），重推要逐个复刻且随两者版本漂移。

## 决定（2026-10-31，`42939514`）
- 采集渲染时，在 6D465F 与 6D4664 之间用 4AED70 的 hook 逐次记录 SHP 调用的原始参数（surface、convert、shape、frame、point、裁剪到 surface 的 bounds、flags、remap、ZAdjust、梯度、亮度、tint、ZShape、调用者），把画在目标上的调用按原顺序变成 Composite 绘制列表，CPU 重放与 GPU 共用。
- 删除全部对象重推代码；Tile 路径（地形、overlay、建筑、迷雾建筑）仍按状态采集，不变。
- 依据：帧缓存按 shape 和 frame 去重，逐调用记录几乎不增加上传；Ares/Phobos 改写的结果自动包含在调用参数里。

## 边界
- 4AED70 之外的提交（体素、线条、粒子、RING1）不在列表里；未建模的调用（无 Centered、ModeledFlags 之外的 flag、remap、ZShapeFrame≠0）只计数。
- 体素（D3a-3）同理，在最终提交点记录：缓存命中 `707480 → 437A10`、未缓存 `4AF2A0 → 4373B0`、车辆合成 `73B140 → 4373B0`。原生体素缓存按 VoxelIndexKey（不是矩阵）查，命中不再光栅化；缓存只存 8 位索引图，`5F99E0` 清空后指针会复用，所以我们的帧缓存键要带清空次数。

## 验证
GPUINF/GPUANIM/GPUDMG 的 SHP 部分 body=0；GPUSHP 只剩顶部建筑 32 个来源不明的非 4AED70 像素；GPUBLD 的 Tile 回归一致。详见 `src/Render/TerrainGPU.md` 的 D3a-2 一节。
