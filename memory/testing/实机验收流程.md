# 实机验收流程

适用于 GPURender 渲染元素的自动化实机对照。约束以 `AGENTS.md`「隔离实机测试」「验收与交付」为准。

## 1. 构建与部署

```powershell
& 'C:\Program Files\Microsoft Visual Studio\2022\Community\MSBuild\Current\Bin\amd64\MSBuild.exe' Phobos.vcxproj /p:Configuration=Debug /p:Platform=Win32 /m /v:minimal /nologo
```

- 确认退出码为 0 后，才把 `Debug/Phobos.dll`、`Phobos.pdb` 复制到 `Debug/AutomationGame/`（隔离副本，已被 gitignore）。记录 DLL SHA256、提交号和 dirty 状态，避免用旧 DLL 得到假的通过结果。
- 未经授权不要覆盖实际安装 `D:/Ra2`。旧文档里的部署许可不是本次的授权。

## 2. 构造场景（Spawner 直进遭遇战）

- 隔离副本自带 `CnCNet-Spawner.dll` 和 `spawn.ini`（默认 `Scenario=XMP30S6.MAP`，Side=0，1 个 AI，10000 资金，seed 20261028）。
- 启动：`Syringe.exe gamemd.exe --args=-CD -LOG -SPAWN -PhobosAutomation`，环境变量传入随机 `PHOBOS_MCP_TOKEN`，需要日志时加 `PHOBOS_SIDEBAR_TRACE=1`。游戏窗口用 `SW_SHOWNOACTIVATE` 打开，不抢前台。
- 需要特定条目时，用 `Arcana troop.mpr`（标准 ini 格式）派生一张临时地图：设 `MultiplayerOnly=1`，追加类型规则覆盖（放开 `Owner`/`RequiredHouses`、`ForbiddenHouses=none`、`Prerequisite=GACNST`、`TechLevel=1`、三个 `RequiresStolen*Tech=no`），再临时把 `spawn.ini` 的 `Scenario` 指过去。
- **地图 `[Structures]` 里写 `Multi1` 的预置建筑不生效**，改为开局后按 `N`（选中 MCV，状态里应为 `AMCV`）、`D`（展开）。见 [[经验 Spawner 预置建筑不生效]]。
- 1024×768 下 sidebar 每页显示 10 行 20 个槽；建筑页需要超过 20 项才能滚动。放开三方 36 种建筑后可达到 28 项。

## 3. 同帧对照方法

1. `game_pause`，在同一暂停帧依次截 `source=ddraw` 和 `source=gpu`，确认两者 `simulation_frame` 相同。
2. 比较区域只取图标格子 `(874,224)-(1006,730)`，排除未迁移的电力条列（`x≈872`）和页签按钮底边（`y=222–223`）。
3. 统计每像素最大通道差：无叠层时应 ≤1；alpha 叠层（暗化、时钟、文字底色）≤8，两层叠加约 ≤10（RGB565 舍入，已接受）。
4. 同时看并排图和放大 8 倍的差异图，确认位置，不只看数字。
5. Sidebar 坐标：x 起点 856，宽 168；cameo 两列中心约 x=907/970，第一行中心 y≈250，行距 50；页签按钮 y≈210（第一个 x≈895，第二个 x≈925）；底部箭头 y≈747（向下 x≈929，向上 x≈955）。

## 4. 收尾

- 只结束本次自己启动、经 `game_status` 认证过的 PID，不杀端口占用者或用户的游戏。
- 恢复 `spawn.ini`、`RA2MD.INI`（如改过驱动），删除临时地图。
- 证据复制到独立目录 `Debug/AutomationTests/<主题>-<日期>/`（截图、`pairs.jsonl`、debug 日志、临时脚本副本、`build-identity.txt`），检查不含 token。
- 报告时区分「实机验证」「仅编译/单测」「未实现」「受环境限制未验证」；一个后端的结果不能推广到另一个。
