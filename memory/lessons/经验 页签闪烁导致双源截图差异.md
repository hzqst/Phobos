# 经验 页签闪烁导致双源截图差异

- **触发信号**：同一暂停帧（`simulation_frame` 相同）的 ddraw 和 gpu 截图，在第一个 sidebar 页签按钮处出现明显差异：一张是高亮帧，另一张是普通帧。
- **根因/约束**：生产完成后页签按钮会闪烁，闪烁由时间驱动，游戏暂停时也继续。两次截图之间隔了几十毫秒，可能截到不同相位。这不代表 GPU 漏画。
- **正确做法**：暂停时交替连拍多组 ddraw/gpu 的页签裁剪区，确认两个来源都会出现两种帧；把这处差异按 best_effort 记录，并在像素对照区域中排除页签底边（`y=222–223`）。
- **验证方法**：交替连拍时记录各自的亮度均值，两个来源都出现过两种取值（2026-10-29：`[52,111,208]` 与 `[95,178,231]`）。
- **适用范围**：所有由时间驱动的 UI 动画（闪烁、雷达动画等）的双源截图对照。逻辑帧号相同并不能证明两张图严格同步。
- **更强的做法：三张夹逼（2026-10-29，电力条）**：电力条追随（`timeGetTime()>>4`，每步 0..5 单位）在暂停期间仍推进并重画 CPU sidebar。同一次暂停按 ddraw → gpu → ddraw 截三张（`pw.py order:ddraw,gpu,ddraw`），先证明两张 ddraw 自身不同，再把每张按格分类（空/G/Y/D/闪烁），确认 gpu 序列严格介于两者之间（例：G14 → G13 → G12）。稳定后三张最大差回到 0～1。证据 `Debug/AutomationTests/power-gpu/`。
- **资金滚动同样适用（2026-10-29）**：资金按每次 UI Update 调用走一步，暂停期间仍在滚动。三张截图中 gpu 的数值总落在两张 ddraw 之间（例：9890→9880→9880、7685→7697→7700）；数字差异放大成图后直接读数核对。
- **雷达动画用连拍池匹配（2026-10-30）**：雷达开关动画约 64ms 一帧，比单次截图（约 100ms）还快，三张截图只证明顺序。改为开启/关闭时交替连拍 24 张，把同一后端所有 ddraw 的雷达带汇成池，逐张查找 gpu 的完全相同帧；多轮（卖雷达、卖电厂断电、重建电厂）后每个后端都有 6～15 张动画帧完全一致。脚本 `Debug/AutomationTests/radar-gpu/scripts/pool.py`。
